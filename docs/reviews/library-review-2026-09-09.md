**Recommendation.** Keep attune-rag's small, composable architecture and invest next in making its existing reliability promises hold from source checkout through installed package and downstream use. The library has useful foundations: deterministic retrieval, optional semantic tiers, explicit provenance, calibration tools, and reusable corpus/editor interfaces. Its most consequential weaknesses are at the boundaries between those pieces. Adding more retrieval mechanisms before correcting those boundaries would increase the surface that needs verification.

**What to keep.**

1. **A component-sized core.** `CorpusProtocol` and `RetrieverProtocol` let consumers adapt data and retrieval without adopting an application framework. The base package declares five direct dependencies; provider/model dependencies are optional. Preserve that separation. [Corpus contract](../../src/attune_rag/corpus/base.py), [retriever contract](../../src/attune_rag/retrieval.py), [packaging](../../pyproject.toml).
2. **Explainable, deterministic keyword retrieval.** Weighted fields, match reasons, stable tie-breaking, and memoized tokens make failures inspectable. Retain this as the inexpensive baseline and fallback. [Implementation](../../src/attune_rag/retrieval.py).
3. **Opt-in retrieval tiers.** Static embeddings, transformer embeddings, rank fusion, and the confidence gate are explicit choices. The gate really does avoid dense work when keyword confidence is sufficient. Heavy dependencies should remain optional. [Hybrid](../../src/attune_rag/hybrid.py), [transformer](../../src/attune_rag/transformer.py).
4. **Explicit provenance and calibration.** Retrieval sources and model-attributed claim citations are distinct records, and corpus-specific calibration is better than presenting one universal threshold. Extend those foundations with accurate runtime traces. [Provenance](../../src/attune_rag/provenance.py), [pipeline](../../src/attune_rag/pipeline.py).
5. **Meaningful test infrastructure.** The configured compatibility matrix covers three operating systems and Python 3.10–3.13. There are real-corpus assertions, API contracts, and variance-aware measurement tools. Improve the checks' fidelity rather than chasing a larger test count. [Test workflow](../../.github/workflows/tests.yml).
6. **Headless editing with preview/apply separation.** Structured diagnostics, rename plans, diff previews, drift detection, and rollback are useful to multiple consumers. Keep the reusable primitives while fixing their semantic and filesystem guarantees. [Editor](../../src/attune_rag/editor/rename.py).

**Highest-priority reliability findings.** Priority expresses recommended ordering and user impact; it is not a claim about a deployed incident.

1. **P1 — Release artifacts omit retrieval tuning.** `pyproject.toml` declares editor schema and dashboard package data, but not `corpus/summaries_override.json` or `corpus/aliases_override.json`. Both are absent from a fresh sdist and wheel. The loader silently tolerates their absence. Independently building a `git archive HEAD` snapshot through sdist and wheel reproduced the 100% → 80% top-1 drop above. The publish workflow builds and uploads without testing the installed artifact.

   **Proposed acceptance:** Required runtime resources are present in both artifacts; install/import the wheel outside the checkout; run the same locked retrieval and documented-use checks there; compare source and wheel using identical corpus dependencies. Missing mandatory bundled resources must fail clearly. [Package data](../../pyproject.toml), [loader](../../src/attune_rag/corpus/attune_help.py), [publish workflow](../../.github/workflows/publish.yml).

2. **P1 — Dense caches can return stale or wrong-corpus content.** `EmbeddingRetriever._corpus_matrix()` caches by naked `id(corpus)` without retaining identity ownership or checking version. Releasing one `DirectoryCorpus` and constructing another reproduced a hit from the previous corpus when Python reused the object ID. Editing a `DirectoryCorpus(cache=False)` updated `get()` and its version, but the dense retriever still returned old content. Transformer retrieval inherits this cache; the hybrid dense leg uses it too. This could cross data-access boundaries in an application that shares a retriever, but no deployed boundary or security incident was inspected.

   **Proposed acceptance:** Cache ownership remains correct across object lifetimes, content changes invalidate cached entries/matrices, cache growth is bounded, and the effective fingerprint includes summaries, aliases, and cross-links. Current corpus versions omit some of those scoring inputs. [Dense cache](../../src/attune_rag/embedding.py), [corpus version](../../src/attune_rag/corpus/directory.py).

3. **P1 — Severe quality failures can become successful CI steps.** A mocked faithfulness score of 0.50 made the real benchmark return 1 and emit a failing report. Replaying the actual workflow shell converted that result into exit 0 with `inconclusive=true`, skipping the threshold check. The same catch-all handles deterministic benchmark failures. Separately, all-NaN metric values passed the threshold checker. Performance measurement crashes also become advisory success; only keyword and pipeline CPU metrics currently block on measured regressions.

   **Proposed acceptance:** Distinguish measured regression, invalid measurement, and known external unavailability. A valid failing report must be checked even if the benchmark returns nonzero; reject nonfinite metrics; replay these outcomes through workflow-level tests. Preserve a deliberate policy for genuine provider outages without treating failures as evidence of quality. [Benchmark workflow](../../.github/workflows/benchmark.yml), [threshold checker](../../scripts/check_thresholds.py), [performance workflow](../../.github/workflows/perf.yml).

4. **P1 — Native citations do not preserve the grounding contract.** The native path does not pass the selected template's grounding instructions into the provider's supported `system` parameter. Selecting `strict` therefore does not deliver its restriction. The model receives full documents, while `RagResult.context` is truncated by the 20,000-character joiner. A probe sent 25,011 document characters, but recorded only 20,000 context characters; a fact at the end was sent but absent from the evaluation context. This is a payload/record mismatch, not a measured hallucination rate.

   **Proposed acceptance:** One grounding-policy decision drives both generation paths; strict mode reaches the provider; recorded context identifies the exact supplied evidence and truncation; context budgets apply consistently; tests inspect actual provider payloads. [Pipeline native path](../../src/attune_rag/pipeline.py), [prompt joiners](../../src/attune_rag/prompts.py).

5. **P1 — Ordinary alias renames can damage a valid corpus.** Renaming a quoted multiword alias updates body references while leaving its declaration unchanged. Renaming an alias to `true` writes an unquoted YAML boolean, causing the alias to disappear from the index. Template-path rename also leaves configured cross-links pointing at the old path and loses outgoing links on reload.

   **Proposed acceptance:** Supported strings retain YAML scalar meaning; declarations and references change together; incoming/outgoing cross-links survive path renames; public preview/apply/reload tests find no new broken references. [Rename](../../src/attune_rag/editor/rename.py), [reference contract](../../src/attune_rag/editor/references.py).

**Other confirmed issues that belong in a hardening plan.**

6. **Fallback is not enforced abstention.** `run_and_generate()` still calls the provider when retrieval returns no hits, including when `prompt_variant="strict"`. The fallback asks for an honest answer and does not carry the strict template. The 92% → 8% claim describes hit leakage, not generated false answers. Define the desired no-evidence behavior explicitly; a provider-free refusal and an explicitly permitted ungrounded answer are different product policies. [Pipeline](../../src/attune_rag/pipeline.py), [negative benchmark](../../src/attune_rag/benchmark.py).
7. **Degradation is incompletely visible.** Hybrid catches every `RuntimeError` under a missing-extra assumption, sets a disabled flag, then calls the same failed embedding object again on the next query. The current test checks returned paths but not call count. Distinguish typed setup failures from execution defects, expose actual fallback reasons, and verify the sequence. [Hybrid](../../src/attune_rag/hybrid.py).
8. **The async convenience method blocks on synchronous retrieval enhancements.** Three concurrent generation calls with 100-ms expansion stubs took approximately 317 ms because expansion ran serially on the event loop. A standalone async expander helper exists but is unused by the pipeline. Define the concurrency contract and test event-loop responsiveness and cancellation. [Pipeline](../../src/attune_rag/pipeline.py), [expander](../../src/attune_rag/expander.py).
9. **Terminal automation and quick starts fail.** Fresh-process `attune-rag query --json` writes an informational log line before the JSON; `json.loads(stdout)` fails despite exit 0. The README's `[h.entry.path for h in result.citation.hits]` raises `AttributeError` because those objects have `template_path`. Execute examples verbatim and require clean stdout for machine-readable commands. Consider making query-content logging configurable. [CLI](../../src/attune_rag/cli.py), [README](../../README.md).
10. **The default Gemini model has been shut down.** The adapter defaults to `gemini-2.0-flash`. Google's official page states that it shut down June 1, 2026. This was verified against provider documentation, not a live API call. Select and validate a supported replacement, and keep examples/model lifecycle checks current. [Adapter](../../src/attune_rag/providers/gemini.py), [Google source](https://ai.google.dev/gemini-api/docs/models/gemini-2.0-flash).
11. **Citation formatting loses supporting excerpts.** Distinct claims citing different excerpts from one document share one footnote, which only retains the first excerpt. Preserve all distinct evidence with unambiguous claim mapping. [Formatter](../../src/attune_rag/provenance.py).
12. **Editor boundary cases need real diagnostics and apply-time validation.** Numeric YAML keys can crash lint; an unclosed frontmatter block can yield no diagnostic. In a separate filesystem-change scenario, a symlink introduced between valid preview and apply redirects a file move outside the corpus. This requires intervening filesystem access; it is not evidence of remote exploitation. Ordinary edits also change permissions from 0644 to 0600. Validate containment at apply time, preserve file metadata, and describe multi-file rollback as best effort. [Lint](../../src/attune_rag/editor/lint.py), [apply](../../src/attune_rag/editor/rename.py).
13. **Corpus-authoring documentation disagrees with the loader.** Frontmatter summary and related fields do not populate the corresponding retrieval fields in the default guide's constructor; those fields come from configured sidecars. The guide describes 1,200 content characters while keyword scoring uses a 500-character preview. The entry docstring claims frontmatter is stripped, but the loader retains it. The README parser description also accepts a full template conceptually, while the parser accepts only a YAML block. Choose and test a coherent public contract. [Guide](../USER_CORPUS_GUIDE.md), [loader](../../src/attune_rag/corpus/directory.py), [schema parser](../../src/attune_rag/editor/schema.py).
14. **Cache pricing and placement claims need correction.** The README says the one-hour prompt cache has the same per-token price. Anthropic documents 5-minute writes at 1.25× base input price and one-hour writes at 2×. The provider marks the first citation document and claims that includes later documents; documented cache semantics cover the prefix through the marked block. Reconcile the wire payload and usage evidence before promising savings. [Provider](../../src/attune_rag/providers/claude.py), [Anthropic source](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).

**Pushback on positioning and measurement.**

The library's strongest evidence supports curated developer-documentation retrieval. Corpus B and C each contain eight Markdown documents, totaling about 2.0 KB and 1.7 KB respectively. The transformer headline's hard subset contains 20 queries. These fixtures are useful stress tests, but they do not establish performance across large, changing, multilingual, or long-document collections. Publish denominators and configurations next to percentages. Keep a held-out evaluation set separate from calibration and tuning.

The current top-k calculation asks whether at least one acceptable document was retrieved. Many queries list alternative acceptable paths. That can be the right success criterion, but it should not imply that every document needed for a complete answer was found. Faithfulness also needs answer-utility and refusal measurements: declining every question can be faithful without being useful.

The README's quoted quality thresholds differ from the active threshold file, which specifies precision@1 0.975, recall@3 1.0, and faithfulness 0.9698. Faithfulness is conditional, several performance axes are advisory, and real-model validation is manual. Label enforced, advisory, historical, and unmeasured claims explicitly. No current branch-protection or remote-check state was inspected.

**Utility opportunities after the correctness work.**

1. Add a compact per-request diagnostic record: effective corpus fingerprint, retriever/model configuration, selected route, degradation reason, context budget/truncation, and timing boundaries. This turns intermittent wrong answers into replayable cases. Avoid treating the existing retriever-relative confidence number as a probability.
2. Improve bring-your-own-corpus onboarding with working examples, a lint/calibration report, persistent calibration metadata, and a clear supported corpus envelope. Make the existing terminal path dependable before building another UI.
3. Explore an optional section/chunk corpus adapter for long Markdown documents, preserving original path and section/offset provenance. Current keyword and embedding previews only score early content. Measure recall improvements and memory/latency tradeoffs on representative data before choosing an index or database.
4. Keep broader frameworks, agent orchestration, external vector stores, and heavyweight defaults outside the immediate reliability program. Existing protocols already provide integration seams. More infrastructure is justified by measured workloads, not by competitor feature counts.

**Proposed sequence, pending collaborative scoping.**

| Milestone | Intended outcome | Countercase/tradeoff |
|---|---|---|
| 1. Artifact and measurement integrity | Built distribution preserves source behavior; measured regressions cannot pass as inconclusive success | Requires careful distinction between real regressions and external-service outages |
| 2. Corpus and editing correctness | No stale/wrong-corpus hits; valid edits preserve references and metadata | Fingerprints and writable-corpus contracts need compatibility decisions |
| 3. Grounding and runtime behavior | Consistent strict/no-evidence policies, truthful context/provenance, visible degradation, responsive async calls | Changing fallback defaults could break callers; policy must be explicit |
| 4. Public usage and credible evidence | Working CLI/examples, supported provider defaults, accurate claims, representative evaluation | Broader real-model/live-provider validation has dependencies and costs to scope separately |

The smallest urgent unit is packaging the missing data and proving source/wheel parity. The larger reliability program includes cache isolation, CI outcome semantics, generation contracts, and safe editing. Keep those as independently reviewable milestones so the broader plan does not delay the urgent repair.
